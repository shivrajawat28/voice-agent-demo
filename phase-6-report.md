## 2. Root Cause of the Beep (Source-Level Evidence)

During manual browser testing in Phase 5, the user observed that selecting `TTS: Gnani AI (Mock/Adapter)` produced a short beep (tone) instead of spoken Hindi.

### Source-Level Diagnosis
1. **The Audio Generator**:
   In `backend/app/providers/mock_tts.py`:
   ```python
   def generate_synthetic_wav(duration_seconds: float = 1.0, frequency_hz: float = 440.0) -> bytes:
       ...
       # Generate a soft sine tone
       for i in range(total_samples):
           envelope = min(1.0, i / 800.0) * min(1.0, (total_samples - i) / 800.0)
           sample_val = int(amplitude * envelope * math.sin(2.0 * math.pi * frequency_hz * i / sample_rate))
           frames.extend(struct.pack("<h", sample_val))
   ```
   `generate_synthetic_wav()` generates a pure sine wave tone at 360 Hz (for Hindi) or 440 Hz (for English). This mathematical sine wave produces a clear, audible electronic "beep/tone".
2. **The Delegation Chain**:
   In Phase 5, `GnaniTTSProvider` (`backend/app/providers/gnani_tts.py`) had:
   ```python
   if not self.is_live_ready():
       if self.allow_mock_fallback and self._mock_provider:
           return await self._mock_provider.synthesize(...)
   ```
   Because `GNANI_API_KEY` was not configured in `backend/.env`, `is_live_ready()` returned `False`.
   `GnaniTTSProvider` silently delegated to `MockTTSProvider`, which returned the 360Hz sine-wave WAV bytes.
3. **The Playback**:
   The backend returned HTTP 200 with Content-Type `audio/wav`. The frontend received the audio blob and played it via `VoiceController.playAudioBlob()`. The user heard the sine-wave beep and naturally questioned why Gnani AI was producing a tone rather than spoken speech.

### Conclusion
The beep was **not** a network failure, corrupted WAV header, sample-rate mismatch, or playback error. It was a deliberate mathematical sine-wave test tone generated by `MockTTSProvider` that was being served silently when `GNANI_API_KEY` was unconfigured.
